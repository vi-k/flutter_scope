# Шаблоны для редакторов

> Перевод `ide/README.md` (blob `12bbeb943f50f3786f83000ef065f17ed80a8c9c`).
> Правится в том же коммите, что и оригинал; проверка — `sh docs/ru/check.sh`.

Одиннадцать шаблонов на тот код, который у скоупа приходится писать всегда:
скелеты классов всех семейств, контейнер зависимостей и строка аксессора.

Скелеты выписывают аксессоры **статическими методами самого скоупа**, так что
потомок читает `App.select(context, …)`. Для того шаблон и нужен: эти обёртки
стоили набора, а шаблон его уже оплатил. Объекты `ScopeAccess` — второй ответ на
ту же цену, для кода, который пишут руками; `scopo-access` вставляет такой
объект тому скоупу, которому он милее.

Два файла, один набор. Их поддерживают парой вручную, и тест
(`test/ide_snippets_test.dart`) краснеет, если шаблон появился в одном формате
и не появился в другом.

## VS Code

А также Cursor, Windsurf и Antigravity — формат у них общий.

Файл едет вместе с пакетом, то есть уже лежит на вашей машине. Найдите его и
скопируйте в проект:

```sh
mkdir -p .vscode
cp "$(find ~/.pub-cache/hosted/pub.dev -maxdepth 1 -name 'scopo-*' | sort -V | tail -1)"/ide/scopo.code-snippets .vscode/
```

Чтобы поставить их сразу для всех проектов, выполните **Snippets: Configure
Snippets** из палитры команд, выберите Dart и вставьте содержимое туда.

## IntelliJ IDEA и Android Studio

Кнопки импорта на странице Live Templates в новых версиях больше нет.
Вместо этого файл кладут в каталог настроек IDE, в подпапку `templates/`, под
именем группы, которую он объявляет:

```sh
# Android Studio на macOS; для IntelliJ IDEA каталог —
# ~/Library/Application Support/JetBrains/<продукт>/
DIR=~/Library/Application\ Support/Google/AndroidStudio<версия>/templates
mkdir -p "$DIR"
cp "$(find ~/.pub-cache/hosted/pub.dev -maxdepth 1 -name 'scopo-*' | sort -V | tail -1)"/ide/scopo-live-templates.xml "$DIR/scopo.xml"
```

Имя файла обязано совпадать с группой: XML объявляет `scopo`, значит файл —
`scopo.xml`. Перезапусти IDE, и шаблоны появятся в
**Settings → Editor → Live Templates** группой `scopo`.

## Сами шаблоны

| набрать | получить |
| --- | --- |
| `scopo-scope` | полный `Scope`: виджет, автоматические зависимости, состояние, статики |
| `scopo-autodeps` | дерево `ScopeAutoDependencies`, которое разбирает себя само |
| `scopo-deps` | рукописный контейнер: неизменяемый, с разбором, до которого доходит отмена |
| `scopo-lite` | `LiteScope` и его состояние |
| `scopo-widget` | `ScopeWidgetBase` |
| `scopo-model` | `ScopeModelBase` над обычным объектом |
| `scopo-notifier` | `ScopeNotifierBase` над `Listenable` |
| `scopo-async` | `AsyncScopeBase` |
| `scopo-data` | `AsyncDataScopeBase` |
| `scopo-controller` | `AsyncControllerScopeBase` и контроллер, которым он владеет |
| `scopo-access` | строку аксессора — для скоупа, которому милее `ScopeAccess` |

## Что проверено, а что нет

Каждый скелет, который эти шаблоны вставляют, компилируется: каждый
разворачивают с именами по умолчанию в собственный файл в `test/ide/`, а их
`flutter analyze` проверяет наравне с остальными файлами пакета. По файлу на
скелет — потому что несколько из них объявляют класс с одним и тем же именем по
умолчанию: в редакторе это правильно, в одной библиотеке — конфликт. Шаблон, переставший
быть валидным Dart, роняет гейт.

**Live templates проверены отчасти.** Сьюта держит их на том же наборе, что и
сниппеты, на двух правилах XML, которые нарушает правка руками, на
интеллиджевском способе экранировать доллар, на списке, который предлагает
табстоп, и на контексте каждого шаблона — но что сделает с файлом редактор,
показывает только импорт. Android Studio его приняла в августе 2026-го; если
какая-то версия шаблон отвергнет, об этом стоит сообщить.

Файл, который редактор отверг, — это не файл с одним сломанным шаблоном: группа
не появляется целиком, и почему — не говорится.

Контекстов в деле три, и плагину Dart принадлежат только два. `DART` — его
общий, он предлагает шаблон везде в Dart-файле; `DART_STATEMENT` сужает это до
позиций оператора, то есть до тела функции. Третий, `DART_TOPLEVEL`, даёт
плагин **Flutter**, и именно его объявляют десять скелетов классов — тот же
контекст, что у собственных `stless` и `stful` Флаттера. Без этого плагина они
не предлагаются вовсе.

Строка аксессора берёт `DART`, и узкий контекст ей не подходит: она идёт в тело
класса, а тело класса — не позиция оператора, так что `DART_STATEMENT` там её
не предложит никогда. Для скелета класса `DART` слишком широк — тот вылезал бы
внутри тел методов, — а для члена он ровно тот.

Скелеты к тому же вставляются как написаны, а не переформатируются редактором
(`toReformat="false"`): они уже уложены `dart format`, что проверяет гейт, а
собственный форматтер IDE — не он.
