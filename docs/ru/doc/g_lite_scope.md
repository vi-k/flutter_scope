# LiteScope

> Перевод `doc/g_lite_scope.md` (blob `cdb441710ac074a1519a5f9f1467212a65f82dad`).
> Правится в том же коммите, что и оригинал; проверка — `sh docs/ru/check.sh`.

Класс состояния, за которым стоит весь жизненный цикл скоупа, но перед которым
нет контейнера зависимостей. `initState` и `dispose` как обычно, плюс
асинхронные `initAsync` и `disposeAsync`, которых скоуп дожидается, плюс
`notifyDependents`, `close()`, `scopeKey` и ожидание дочерних скоупов.

Это семейство для состояния экрана, владеющего тем, что стоит освобождать
по-человечески, — контроллерами, подписками, сокетом. `Scope` добавляет перед
состоянием контейнер зависимостей; `AsyncScope` убирает состояние и оставляет
только жизненный цикл.

```dart
final class ScreenScope extends LiteScope<ScreenScope, ScreenScopeState> {
  const ScreenScope({super.key, super.scopeKey});

  @override
  Widget? buildOnWaiting(BuildContext context) => const SizedBox.shrink();

  @override
  ScreenScopeState createState() => ScreenScopeState();

  static ScreenScopeState of(BuildContext context) =>
      LiteScope.of<ScreenScope, ScreenScopeState>(context);
}

final class ScreenScopeState
    extends LiteScopeState<ScreenScope, ScreenScopeState> {
  final controller = ScrollController();

  @override
  Future<void> disposeAsync() async => controller.dispose();

  @override
  Widget build(BuildContext context) =>
      ListView(controller: controller, children: const [Text('item')]);
}
```

## Состояние

`LiteScopeState` — это `State` с четырьмя добавками:

| член | что это |
| --- | --- |
| `initAsync()` | асинхронная инициализация; её дожидаются, прежде чем показать готовое состояние |
| `disposeAsync()` | асинхронный разбор; его дожидаются, прежде чем скоуп исчезнет |
| `notifyDependents()` | перестроить подписанных потомков, а не поддерево |
| `close()` | запустить разбор, пока скоуп ещё на экране |

и с тремя собственными свойствами: `params` — виджет скоупа, так что параметры
его конструктора читаются из состояния; `isInitialized`; и `onInitialized()` —
хук, который зовут, когда инициализация полностью завершилась.

Обычные `initState` и `dispose` у `State` продолжают работать и остаются
синхронными. `initAsync` — место для `await`, а `disposeAsync` — то, что
заставляет родительский скоуп (и `close()`) дождаться конца освобождения, а не
запустить его и забыть.

## Две инициализации

Фаз две, и это не одно и то же.

`LiteScope.init()` на **виджете** — предварительная инициализация: поток
`AsyncScopeInitState`, ровно как в теме `AsyncScope`, выполняющийся *до*
создания состояния. По умолчанию он сразу выдаёт `AsyncScopeReady()`, поэтому
большинство скоупов его не переопределяют. Переопределяйте, когда что-то должно
быть готово до `createState`; тогда придётся переопределить и
`buildOnInitializing`, и `buildOnError` — их реализации по умолчанию бросают
`UnimplementedError`, исходя из того, что ненаписанная ветка прогресса — это
ошибка, а не пустой экран.

`LiteScopeState.initAsync()` на **состоянии** — обычная: она выполняется, когда
состояние уже существует, и готовая ветка её дожидается.

`buildOnWaiting` закрывает промежуток до того, как хоть одна из них что-то
выдала, — кадры ожидания `scopeKey` и первого события. Вернуть из него `null`
разрешено, только если переопределён `buildOnInitializing`: что-то на экране
быть обязано.

`wrapState` оборачивает только готовую ветку, поэтому виджет, нужный всем
веткам, строят внутри каждого билдера.

## Доступ из поддерева

```dart
ScreenScope.of(context).controller;                    // состояние
LiteScope.select<ScreenScope, ScreenScopeState, int>(  // одно значение из него
  context,
  (state) => state.itemCount,
);
LiteScope.paramsOf<ScreenScope, ScreenScopeState>(context, listen: false);
LiteScope.selectParam<ScreenScope, ScreenScopeState, Object?>(
  context,
  (widget) => widget.scopeKey,
);
```

`of` и `maybeOf` возвращают состояние и никогда не подписывают — они для вызова
методов. `select` подписывает на одно значение, выведенное из состояния, и
вызывающего перестроят, только когда это значение изменится **и** только если
состояние позвало `notifyDependents()`. Больше за состоянием никто не
наблюдает: изменённое без этого вызова поле не дойдёт ни до кого — тот же
договор, что у `StatefulWidget` с `setState`.

`paramsOf` и `selectParam` делают то же самое для собственных параметров виджета
скоупа. Переоткрывать всё это именованными статиками на скоупе, как `of` выше, —
обычная практика.

## close()

```dart
await ScreenScope.of(context).close();
```

`close()` запускает разбор, пока скоуп ещё на экране, и завершается, когда
утилизация закончена. Готовое поддерево замораживается снимком, поверх
показывается `buildOnClosing`, а элемент остаётся на дереве до самого конца — в
этом и смысл: скоуп, который освобождает что-то заметное время, показывает
«закрываемся…», а не замирает на последнем кадре.

Снимок делается по возможности, и это уточнение точное: барьер снимка ставится,
только если скоуп действительно готов и ещё на дереве, — в любом другом
состоянии освободить барьер было бы некому, и future повис бы навсегда.
Поддерево, которое никогда не рисовалось (внутри `Offstage` или в невыбранной
ветке `IndexedStack`), снять тоже нельзя; после
`ScreenshotReplacer.maxRetries` кадров `close()` идёт дальше, и
`buildOnClosing` рисуется поверх живого поддерева.

Второй вызов `close()` ничего не перезапускает: он присоединяется к уже идущей
утилизации, а не ставит второй барьер.

## Разбор и кто его дожидается

Порядок — тот же, что в теме `AsyncScope`, со вставленными шагами состояния:
предварительная инициализация отменяется, дожидаются дочерних скоупов
(`waitForChildrenTimeout`), выполняется `disposeAsync()` состояния, за ним
обычный `dispose()`, и последним освобождается `scopeKey`, чтобы следующий скоуп
с этим ключом стартовал, только когда этот закончил.

`LiteScope` — такой же `AsyncScopeParent`, как любой асинхронный скоуп: скоупы
под ним встают к нему на учёт, и он дожидается их, прежде чем разбирать себя.
