# utils

> Перевод `doc/j_utils.md` (blob `39a8b80e1944fe657bb34ce550cd37a774164dd0`).
> Правится в том же коммите, что и оригинал; проверка — `sh docs/ru/check.sh`.

Хелперы, которые едут вместе с пакетом, но не принадлежат ни одному семейству
скоупов. Они экспортированы, потому что на них построены сами скоупы, а
приложению обычно нужны те же инструменты; ничему здесь скоуп сверху не нужен.

| хелпер | что это |
| --- | --- |
| `ListenableListenExtension.listen` | подписка на `Listenable` в стиле `Stream` |
| `ListenableSelectExtension.select` | слушатель, который зовут только при изменении выбранного значения |
| `ListenableSelector` | виджетная форма того же селектора |
| `ListenableView` | фасад только для чтения над `Listenable` |
| `StateAsNotifier` | миксин, делающий `State` слушаемым |
| `NavigationNode` | вложенный `Navigator`, удерживающий свои маршруты внутри скоупа |
| `ProgressIterator`, `Progress` | счёт шагов инициализации |
| `ScreenshotReplacer` | замораживает поддерево в изображение, которое оно нарисовало последним |
| `CompareUtils` | четыре функции сравнения с именами |
| `IsBuildingExtension` | строится ли сейчас кадр и как дождаться его конца |

## Слушать Listenable

`addListener` и `removeListener` требуют держать колбэк при себе, поэтому от
замыкания нельзя отписаться, не сохранив его где-то. `listen` вместо этого
возвращает подписку — так же, как `Stream`:

```dart
final subscription = counter.listen(() => print(counter.value));
…
subscription.cancel();
```

`CompositeListenableSubscription` собирает несколько таких подписок и отменяет
их все одним вызовом.

`select` сужает колбэк до одного значения:

```dart
final subscription = model.select(
  (model) => model.userName,
  (model, userName) => print(userName),
);
```

Слушателя зовут, только когда выбранное значение изменилось. Изменение по
умолчанию — это `==`, а `compare:` это заменяет: `identical` для значения,
которое заменяют, а не меняют, сравнение по полям для записи и так далее. Это та
же идея, которой `select` пользуется на скоупе, только без дерева виджетов.

`ListenableSelector` — виджет вокруг того же механизма:

```dart
ListenableSelector<Counter, int>(
  listenable: counter,
  selector: (counter) => counter.value,
  builder: (context, counter, value, child) => Text('$value'),
);
```

Принятый им `child` возвращается в `builder` нетронутым — обычный способ
удержать поддерево вне перестроения.

`ListenableView` заворачивает `Listenable` так, что доступны только
`addListener` и `removeListener`: отдавайте его, когда поддереву можно слушать,
но нельзя уведомлять. `ScopeStateModelView` из темы `ScopeNotifier` — та же идея
применительно к модели состояния.

`StateAsNotifier` работает в обратную сторону: подмешайте его в `State`, и само
состояние становится `Listenable` со своим `notifyListeners()`. Стоящий за ним
`ChangeNotifier` создаётся на первом слушателе и утилизируется вместе с
состоянием, так что состояние, которое никто не слушает, ничего не стоит.

## NavigationNode

Вложенный `Navigator`, чьи маршруты остаются внутри текущего скоупа. Диалог,
шторка или экран, открытые через него, строятся под скоупом, а не над ним, —
поэтому всё, что скоуп предоставляет, доступно и из этих маршрутов, чего нельзя
сказать о корневом навигаторе приложения.

```dart
NavigationNode(child: const ScreenBody())
```

`navigatorKey` открывает внутренний `NodeNavigatorState`, когда пушить нужно
снаружи. `isRoot` помечает узел, который не должен пробрасывать поп дальше.
`onPop` перехватывает системный жест «назад»: верните `true`, чтобы пропустить
поп, `false`, чтобы удержать маршрут, или `Future<bool>`, чтобы решить после
вопроса — обычно после диалога подтверждения.

`PreviousNavigatorExtension.previous` отдаёт навигатор, лежащий над данным, —
так узел пробрасывает поп, с которым не справился сам.

## ProgressIterator

Счёт шагов для инициализации, которая знает, сколько их у неё:

```dart
final progress = ProgressIterator(3);

progress.nextStep(); // 1/3
progress.nextStep(); // 2/3
progress.add(1);     // 3/3
progress.isCompleted; // true
```

`Progress` — производимое им значение: `number`, `total`, `progress` как доля от
0 до 1 и `toString` вида `2/3`. `ScopeAutoDependencies` пользуется ровно этим,
чтобы отчитываться шагом на зависимость, — см. тему `Scope`.

## ScreenshotReplacer

Рисует своего ребёнка один раз, снимает нарисованное и дальше показывает
изображение вместо него. Пакет применяет это в `close()`: последний кадр скоупа
замораживается на время асинхронной утилизации, так что экран закрытия рисуется
поверх неподвижной картинки, а не поверх разбираемого поддерева.

```dart
ScreenshotReplacer(
  onCompleted: () => print('captured, or given up on'),
  child: const HomeScreen(),
);
```

Поддерево, которое никогда не рисовалось — внутри `Offstage` или в невыбранной
ветке `IndexedStack`, — снять нельзя. Поэтому попытки ограничены
`ScreenshotReplacer.maxRetries` кадрами, после чего `onCompleted` зовут всё
равно, а живой ребёнок остаётся на месте. `onCompleted` срабатывает ровно один
раз за состояние, чем бы дело ни кончилось, — в том числе если виджет раньше
убрали с дерева.

## Два маленьких

`CompareUtils` — это `equals`, `notEquals`, `identical` и `notIdentical`
именованными функциями, для мест, принимающих сравнение параметром (в том числе
для `compare:` выше), где tear-off читается лучше лямбды.

`IsBuildingExtension` расширяет `SchedulerBinding`. `isBuilding` говорит,
строится ли кадр прямо сейчас, а `runOutsideFrame(action)` выполняет действие
немедленно, если это безопасно, или в post-frame-колбэке, если кадр в работе.
Этим скоуп удерживает уведомление от попадания в середину сборки.
