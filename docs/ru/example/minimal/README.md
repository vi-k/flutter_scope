Один скоуп, в минимуме файлов: `lib/main.dart`, 245 строк.

```sh
cd example/minimal

```

## Что показывает

`App` — полноценный `Scope` со всеми тремя частями, и файл выложен в том же
порядке:

1. **`App`** — виджет скоупа. Он несёт один параметр, `title`, и открывает
   четыре аксессора, которые скоуп обычно переоткрывает под своим именем:
   `paramsOf` и `selectParam` для параметра, `of` и `select` для состояния.
2. **`AppDependencies`** — контейнер, инициализируемый асинхронно. Ждёт он
   `SharedPreferences`, а сообщаемый прогресс — это тот самый `String`, который
   виден на заставке.
3. **`AppState`** — состояние. Оно читает счётчик из хранилища в `initState`, а
   `increment()` его меняет, зовёт `notifyDependents()` и пишет обратно.

Каждая из трёх веток строится со своим `MaterialApp` — вот что на практике
означает то, что `wrapState` работает только для готовой ветки; ради этого в
файле и существует `_app({required child})`. `pauseAfterInitialization`
выставлен в 500 мс, чтобы заставку вообще можно было разглядеть на быстрой
машине.

`main()` заодно ставит наблюдателя — `ScopeConfig.observer = const
ScopePrintObserver()`, — который печатает по строке на событие жизненного
цикла. Запустите — и в консоли видно, как скоуп инициализируется, сообщает
прогресс, становится готовым и, при закрытии приложения, утилизируется по
порядку.

## Что попробовать

- Передайте `ScopePrintObserver` в `main()` параметр `trace: true`, чтобы
  видеть механику под жизненным циклом — очередь `scopeKey`, защищённые
  потоки, — а не только вехи.
- Заставьте `AppDependencies.init` бросить исключение после первого `yield`,
  чтобы попасть на ветку ошибки.
- Поставьте `ScopeConfig.pauseAfterInitializationEnabled = false`, чтобы
  увидеть, насколько быстро готовая ветка приходит на самом деле.

Темы, стоящие за всем этим, — страницы `Scope` и `debug` в
[документации](https://pub.dev/documentation/scopo/latest/).
