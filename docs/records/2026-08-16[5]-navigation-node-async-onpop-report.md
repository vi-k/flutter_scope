## P2 №14 — асинхронный `onPop` спрашивали дважды и слушали слишком поздно

```dart
if (_navigator.previous case final previous?) {
  switch (widget.onPop?.call(context, result)) {
    case final Future<bool> future:
      future.then((canPop) {
        if (canPop) previous.pop(result);   // когда-нибудь потом
      });
    ...
```

Два дефекта в одном месте:

- **нет single-flight.** Два быстрых системных back запускают два вызова
  `onPop`. Два ответа `true` снимают два внешних маршрута;
- **нет проверки актуальности.** `previous` захвачен до ожидания, а к моменту
  ответа маршрут, на котором стоит узел, мог быть закрыт кем-то ещё или завален
  новым. Тогда `previous.pop(result)` снимает то, что оказалось сверху, — не то,
  о чём спрашивали.

### Что стало

```dart
if (_deciding || _navigator.previous == null) {
  return;
}

switch (widget.onPop?.call(context, result)) {
  case final Future<bool> future:
    _deciding = true;
    final route = ModalRoute.of(context);

    future.whenComplete(() => _deciding = false).then((canPop) {
      if (!canPop || (route != null && !route.isCurrent)) {
        return;
      }
      _navigatorKey.currentState?.previous?.pop(result);
    });
```

`whenComplete` перед `then`, а не `then` с обработчиком ошибки: флаг снимается и
при отказе future, а сама ошибка остаётся видимой, а не проглатывается.

Узел, которого больше нет, отвечает за себя сам: его ключ ни во что не
разрешается. Поэтому обход null-safe и отдельная проверка `mounted` не нужна —
см. ниже, как это выяснилось.

### Тесты

Четыре теста в `test/navigation_node_test.dart`:

| тест | что доказывает |
| --- | --- |
| `asked once, however fast the presses` | два back — один вопрос, один снятый маршрут |
| `answers too late takes nothing` | маршрут узла закрыли снаружи — ответ ничего не берёт |
| `answering under a newer route takes nothing` | маршрут завалили новым — то же самое, и здесь узел **жив** |
| `answering after the node is gone takes nothing` | узел убрали из поддерева, маршрут остался |

Третий и четвёртый существуют порознь именно потому, что нагружают разные
проверки: в третьем работает `route.isCurrent`, в четвёртом — null-safe обход.

### Что показала мутационная проверка

Первая версия правки содержала ещё и `!mounted` в условии. **Мутация,
убирающая его, не роняла ни одного теста** — и разбор показал, что проверка
избыточна: у снятого узла `_navigatorKey.currentState` уже `null`. Проверка
убрана, а не оставлена непроверенной веткой.

Дальше мутация, заменяющая null-safe обход на `_navigator.previous` (с `!`),
тоже никого не роняла — потому что не было теста, где узел исчез, а маршрут
остался. Такой тест дописан (`_RemovableNodeHost`), и после него мутация роняет.

Итог: **четыре мутации, каждая роняет тест** — убрать single-flight, убрать
проверку маршрута, убрать ассерт `navigatorKey`, заменить null-safe обход на
разыменование.

## P3 №17 — новый `navigatorKey` игнорировался

```dart
late final _navigatorKey = widget.navigatorKey ?? GlobalKey<NodeNavigatorState>();
```

`late final` читается один раз. Виджет, перестроенный с другим ключом, оставлял
узлу прежний: `currentState` нового ключа так и оставался `null`.

Честно принять новый ключ нельзя: ключ — это то, с чем построен `Navigator`, а
смена ключа заставляет Flutter выбросить элемент и построить новый. То есть
вложенный стек был бы потерян. Хуже того, это ровно то, что происходило бы при
`NavigationNode(navigatorKey: GlobalKey(), …)` внутри `build` родителя —
сброс навигатора на каждом кадре. Нынешний `late final` от этого молча защищал.

Поэтому смена ключа **отклоняется ассертом**, как и смена конструктора модели в
волне 4. Объявленный ключ хранится отдельно от используемого (`_declaredKey`),
чтобы одинаково ловились и подмена ключа, и появление ключа у узла, который
строился без него.

**Ассерт стоит в `build`, а не в `didUpdateWidget`.** Первая версия стояла там,
и это сломало кадр: исключение из `didUpdateWidget` бросает обновление на
середине, и следом прилетает вторичный ассерт самого фреймворка
(`'_dependents.isEmpty': is not true`) при разборе. В `build` исключение ловит
build error boundary Flutter, и тест получает чистый `AssertionError`.
