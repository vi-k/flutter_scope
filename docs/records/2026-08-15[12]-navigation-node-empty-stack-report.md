# Узел, опустошавший сам себя, — отчёт

> **Состояние на 2026-08-15:** исправлено, полный гейт пройден.
> **Что это:** отчёт о TDD-исправлении дефекта, найденного владельцем на уроке 5
> примера `navigation_node`: `pop()` на первой странице узла снимал эту
> страницу и оставлял узел с пустым стеком.
> **Связанные записи:** `2026-08-15[11]-navigation-node-example-design.md`,
> `2026-08-15[10]-navigation-onpop-regressions-report.md`,
> `2026-08-14[10]-project-review.md`.

## Причина

Проброс попа наружу держался на `_HookEntry` — записи локальной истории на
первой странице узла. Снявшись, запись вызывала `onRemove`, а тот отдавал поп
навигатору выше.

У этого механизма два изъяна, и оба видны на одной кнопке.

У узла с `isRoot: true` запись не ставилась вовсе, поэтому `Navigator.pop()`
уходил прямо в `NavigatorState.pop()` и снимал единственную страницу. Навигатор
оставался с пустым стеком — на экране дыра на месте узла. При этом dartdoc
обещает обратное: «A root node keeps a pop to itself».

У обычного узла запись **одноразовая**: снявшись, она пробрасывала поп и больше
не возвращалась (`restoreMarker()` вызывался только когда `onPop` отвечал
«остаться»). Со второго `pop()` такой узел вёл себя как root — то есть пустел.

## Исправление

Решение переехало из `onRemove` в `NodeNavigatorState.pop()`, где видно и
состояние стека, и `isRoot`:

```dart
if (canPop()) {
  super.pop(result);
  return;
}

if (!isRoot) previous?.maybePop(result);
```

`canPop()` здесь — тот самый честный, введённый предыдущей волной: он не считает
служебный маркер маршрутом, который узел может закрыть. Поэтому «внутри пусто»
определяется одним условием и для системного back, и для ручного `pop()`.

Маркер остался, но сменил роль. Он больше не расходуется: теперь он нужен, чтобы
первая страница отвечала `willHandlePopInternally` и `maybePop` попадал в наш
`pop()`, а не проходил мимо узла, — и чтобы `AppBar` на этой странице рисовал
стрелку «назад» (`impliesAppBarDismissal` у `LocalHistoryEntry` истинен по
умолчанию). Раз запись не снимается, стали недостижимы `_HookEntry.onRemove`,
поле `_interceptedResult` и `restoreMarker()` в `_decideOutside`; всё это
удалено в том же коммите. Проброс теперь работает столько раз, сколько его
просят.

## TDD

Дефект найден владельцем вручную и сперва воспроизведён временными пробами:
root-узел — `node content = 0` после `pop()`; обычный узел — `0` со второго
`pop()`. Пробы удалены.

Четыре постоянных теста в `test/navigation_node_test.dart`:

| тест | до правки |
| --- | --- |
| `pop() on the only page of a root node keeps the page` | RED |
| `an ordinary node keeps its page when there is nowhere to forward a pop` | RED |
| `an ordinary node forwards a pop it cannot handle` | проходил — страховка |
| `a root node does not forward a pop even when it could` | проходил на исходном коде, но нужен: без него `isRoot` в новой ветке не нагружен |

Мутационная проверка:

| мутация | результат |
| --- | --- |
| убрать guard `if (canPop())` целиком | 18 → 14 зелёных, падает 4 |
| пробрасывать и у root-узла | 18 → 17, падает 1 |
| не пробрасывать вовсе | 18 → 17, падает 1 |

В примере `navigation_node` добавлен тест урока 5: правая витрина (root) держит
своё содержимое, левая пробрасывает поп и закрывает урок. До правки урок 5
показывал ровно этот дефект — пустеющий бокс.
