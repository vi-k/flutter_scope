# Шестнадцать имён U3: проверка по сигнатурам

> **Состояние на 2026-08-24:** измерение проведено, кода не тронуло.
> Записанная точка входа U3 отработана и дала отрицательный результат:
> убирать из шестнадцати нечего. Решение владельца по самой U3 —
> по-прежнему «отложено».
> **Что это:** отчёт о проверке шестнадцати публичных имён, которых нет
> нигде снаружи, — стоят ли они в публичных сигнатурах.
> **Связанные записи:** `2026-08-23[1]-consumer-review.md` (находка U3 и её
> вердикт), `2026-08-24[3]-navigation-node-extraction-report.md` (после него
> публичных типов стало 99).

## Что проверялось

Вердикт U3 кончался обещанием: «зато шестнадцать имён не встречаются нигде
снаружи… Часть из них наверняка обязана быть публичной, потому что стоит в
сигнатурах, — это не проверено по коду. **Здесь и лежит настоящее сокращение
поверхности, а не в перекладывании между барелями.**»

Проверялось ровно это обещание, и оно не подтвердилось.

## Метод

1. Список шестнадцати сверен с деревом: все на месте, ни одно не уехало с
   `NavigationNode`.
2. Поиск по отслеживаемым исходникам — `example/**`, `doc/*.md`, `README.md`,
   `ide/**`, `docs/ru/**`. Снаружи нет ни одного, утверждение находки верно.
3. Все шестнадцать спрятаны из бареля (`hide` в `lib/scopo.dart`) и прогнаны:
   корневой `flutter analyze`, оба примера, `dart doc --dry-run`.
4. Написана **проба настоящего потребителя** — файл в `example/minimal/lib/`,
   который импортирует только `package:scopo/scopo.dart` и делает то, чему учат
   темы: строит своё семейство на паре `Core`/`ElementBase`, объявляет тип,
   который возвращает `listen()`, и разбирает `switch` по состоянию
   зависимости. Проба прогнана дважды — с целым барелем и со спрятанными
   именами.
5. Документация сгенерирована в обоих состояниях (`dart doc --output` в
   scratchpad, `doc/api` не тронут) и сравнена по числу страниц, ссылающихся на
   каждое имя.

Барель восстанавливался копией из scratchpad, не `git checkout` (грабля волны
25). После проверки дерево чистое, `git diff` пуст.

## Что показал прогон со спрятанными именами

**Оба примера — чисто.** Ни одной ошибки в `example/minimal` и
`example/scopo_demo`. То есть обычному потребителю, который берёт семейства
как они есть, шестнадцать имён действительно не нужны — находка права.

**`dart doc --dry-run` — 0 warnings, 0 errors.** Тоже в обоих состояниях. Это
первый результат, который стоит унести: **гейт §6 не защищает от такого
решения вовсе.** Публичный член, чей тип не экспортирован, dartdoc не считает
ошибкой — он просто перестаёт делать ссылку.

**Сьюта пакета — 147 замечаний, 114 из них ошибки**, все в `test/`:
`lite_scope_test.dart` (127 замечаний), `scope_observer_test.dart` (18),
`scope_auto_dependencies_test.dart` и `cleanup_after_user_error_test.dart` (по
одному). Тесты строят свои семейства на `LiteScopeCore`, `LiteScopeCoreState`,
`LiteScopeElementBase`, `ScopeCoreState` и `AsyncControllerScopeElementBase`,
то есть пакет **сам пользуется этим слоем как точкой расширения** — из бареля,
а не через `src/`.

## Три имени запрещает анализатор

Проба потребителя падает на трёх именах, и это не рассуждение, а вывод
`flutter analyze`:

```
error • 'PlayerElement' doesn't conform to the bound
        'AsyncControllerScopeElementBase<PlayerScope, PlayerElement, PlayerController>'
        of the type parameter 'E'
error • Undefined class 'ListenableSubscription'
error • Undefined class 'ScopeDependencyAnyFailed'
```

- **`AsyncControllerScopeElementBase`.** `doc/async_controller_scope.md:43`
  учит `AsyncControllerScopeCore` — «for a scope that needs its own element», —
  а элемент этот обязан наследовать `AsyncControllerScopeElementBase`: это
  граница типового параметра `E`. Использовать задокументированный класс, не
  называя спрятанный, нельзя;
- **`ListenableSubscription`.** Возвращаемый тип публичного `listen()`,
  параметр публичного `CompositeListenableSubscription.add()` и надтип
  публичного `ListenableSelectSubscription`. Поиск по примерам его не нашёл
  только потому, что там пишут `final sub = x.listen(…)`: **вывод типов прячет
  имя, без которого код всё равно не живёт**;
- **`ScopeDependencyAnyFailed`.** Образец в `switch` по
  `ScopeDependencyState` — единственный способ поймать оба провальных листа
  (`ScopeDependencyFailed` и `ScopeDependencyDisposalFailed`) одним `case`.
  Сам пакет так и делает, `scope_dependency_group.dart:127`.

Ещё одно наблюдение из той же пробы: когда `AsyncDataScopeElementBase` спрятан,
анализатор всё равно называет его в сообщении — «Missing concrete
implementations of `AsyncControllerScopeElementBase.createController` and
**`AsyncDataScopeElementBase.buildOnState`**». То есть потребителя посылают
реализовать член класса, которого в API нет.

## Остальные тринадцать — середина поверхности, а не её край

Ключевой факт, ради которого стоило рисовать цепочки: **ни одно из шестнадцати
имён не лист.** Каждое стоит между двумя публичными классами, и почти у всех
снизу — класс, который показан в демке или в теме.

Цепочка виджетов:

```
ScopeWidgetCore ← ScopeModelCore ← AsyncScopeCore ← LiteScopeCore*  ← ScopeCore*
                                                  ← AsyncDataScopeCore* ← AsyncControllerScopeCore
```

Цепочка элементов:

```
ScopeWidgetElementBase ← ScopeModelElementBase ← ScopeNotifierElementBase
    ← AsyncScopeElementBase ← LiteScopeElementBase*    ← ScopeElementBase*
                            ← AsyncDataScopeElementBase* ← AsyncControllerScopeElementBase*
```

Звёздочкой — те, что в списке шестнадцати. Что из этого следует:

- **`ScopeCore` — прямой надкласс `Scope`**, а `LiteScopeCore` — прямой надкласс
  `LiteScope` (`scope_base.dart:49`, `lite_scope_base.dart:10`). Это не
  внутренности рядом с поверхностью, это то, на чём стоит главный класс пакета.
  Всё, что `Scope` наследует, страница `Scope` подписывает «inherited from
  `ScopeCore`»;
- **`AsyncDataScopeCore` — прямой надкласс задокументированного
  `AsyncControllerScopeCore`**, а `AsyncDataScopeElementBase` — надкласс
  элемента того же семейства;
- **`AsyncScopeModel`** — типовой аргумент, который задокументированный и
  показанный в демке `AsyncScopeCore` закрепляет в своём надтипе
  (`extends ScopeModelCore<W, E, AsyncScopeModel>`), и объявленный тип
  публичного `AsyncScopeElementBase.model`;
- **`ScopeDependencyAnySuccess` и `ScopeDependencyAnyCancelled`** — два
  оставшихся промежуточных `sealed` того же трёхчастного деления, что и
  `ScopeDependencyAnyFailed`, который анализатор уже отстоял. Оставить одного
  из трёх нельзя: деление либо есть, либо нет;
- **`ScopeDependencyMixin`** — миксин, на котором стоит публичный
  `ScopeDependencyGroup`, и путь к рукописной `ScopeDependency`;
- **`ScopeModelInheritedElement`** — единственное имя, за которым не стоит ни
  сигнатуры, ни границы: его только реализует публичный
  `ScopeModelElementBase`. Но это третий член тройки с
  `ScopeInheritedElement` и `ScopeInheritedWidget`, а те остаются (второй —
  граница `ScopeModelContext`), и `doc/base.md:82` учит именно этой тройкой.

**Слой `Core`/`ElementBase` — заявленная точка расширения, а не утечка.**
`doc/scope_widget.md:5`: «`ScopeWidgetCore` and `ScopeWidgetElementBase` are the
pair every other family extends», и там же, ниже, — «Read the rest when writing
a scope of your own» с рабочим примером своего семейства. Пять семейств из
восьми показаны в темах и демке, три — нет; спрятать эти три значит сказать
«своё семейство писать можно, но не с зависимостями, не облегчённое и не над
данными», не объяснив почему.

**И все шестнадцать помечены `{@category}`** — каждое положено в тему руками.
Ни одно не «просочилось».

## Цена, если убирать всё равно

Сгенерированная документация ссылается на эти шестнадцать имён **с 263 страниц**
(от 8 у `ScopeDependencyAnySuccess` до 23 у `AsyncScopeModel`,
`LiteScopeElementBase` и `ListenableSubscription`). Прятание убирает их
страницы и превращает все 263 ссылки в неподсвеченный текст — **молча**, потому
что `dart doc` при этом говорит «0 warnings».

Плюс сьюта: 114 ошибок компиляции в четырёх файлах, лечится переводом этих
тестов на прямой импорт `src/`. Это выполнимо, но означает, что пакет
перестаёт проверять свою точку расширения так, как её видит потребитель.

## Вывод

Обещание вердикта U3 — «здесь и лежит настоящее сокращение поверхности» — не
подтвердилось. Из ста двух имён (теперь девяноста девяти) шестнадцать не
используются снаружи **потому, что это середина иерархии, а не потому, что они
лишние**. Убрать без потерь нельзя ни одного; убрать с потерями можно шесть-восемь,
и цена — дыры в середине задокументированной цепочки наследования.

Настоящий рычаг у U3 остаётся прежним и прежде измеренным: разделение барелей,
23 имени из 99. Это решение владельца и ломающая правка.

## Грабли, найденные по ходу

- **`doc/api/` — 7,1 МБ сгенерированной документации в рабочем дереве.** Она в
  `.gitignore` и в `.pubignore`, но `grep -r` по репозиторию её видит, и первый
  же поиск по шестнадцати именам дал 105–260 «попаданий снаружи» там, где на
  самом деле ноль. Искать надо `git grep`, а не `grep -r`. Вдобавок она
  устарела: в ней ещё стоят `disposeAsync` и прочие имена до переименований
  18 августа;
- **`dart doc` не предупреждает о публичном члене, чей тип не экспортирован.**
  Проверено обоими прогонами: 0 warnings и до, и после. Гейт §6 такую правку
  пропустит целиком, и заметит её только читатель документации — по мёртвой
  ссылке;
- **вывод типов прячет имя, которое всё равно обязано быть публичным.** Поиск
  по примерам не нашёл `ListenableSubscription` ровно потому, что примеры
  пишут `final sub = …`. Список «не встречается снаружи» надо проверять по
  сигнатурам, а не по вхождениям.
