# `ScopePhase.build`: отказ сборки, который слышит наблюдатель

> **Состояние на 2026-08-22:** дизайн утверждён владельцем, работа начата.
> **Что это:** дизайн последней недостающей фазы наблюдателя — отказ сборки
> скоупа (`buildOn*`, `ScopeWidget.build`, `ScopeModel.build`) сейчас ловит
> граница ошибок Flutter и до `ScopeConfig.observer` не доходит.
> **Связанные записи:** `2026-08-19[1]-scope-observer-design.md` (сам
> наблюдатель), `2026-08-20[1]-project-review.md` (четвёртое ревью).

## 1. Зачем

**Осталась ровно одна семья пользовательских точек без отчётности.** Работа
2026-08-20 свела к наблюдателю все хуки жизненного цикла — `create`,
`onMount`, `init`, `initScope`/`initData`/`initDependencies`, `onUnmount`,
`disposeScope`, `dispose` зависимости, контроллера и `ScopeModel`. Поиск по
соседям тогда же показал, что незакрытой осталась одна семья: то, что зовётся
из сборки. Записано в `docs/handoff.md`, раздел «Открыто, вне списка ревью»:

> **отказ `buildOn*` до наблюдателя не доходит — и это граница, а не пробел.**
> `buildOnReady`, `buildOnProgress`, `buildOnError`, `buildOnWaiting`,
> `buildOnClosing` зовутся из сборки, и их отказ ловит собственная граница
> ошибок Flutter, отвечая `ErrorWidget`. Отдельного `ScopePhase` под сборку
> нет, и заводить его — отдельное решение.

Решение принято владельцем 2026-08-22: заводить.

**Граница ошибок Flutter — не отчётность.** Она делает `ErrorWidget` и пишет в
`FlutterError`, то есть отвечает **экрану**. Наблюдателя заводят затем, чтобы
приложение слышало о скоупах — своим каналом, с целью, фазой и `debugLabel`. У
скоупа, чей `buildOnReady` упал, в записи наблюдателя не остаётся ничего: он
проинициализировался, отчитался `onReady` — и дальше тишина, хотя на экране
красный прямоугольник.

**Это ровно тот же довод, что закрыл `init()`.** Комментарий на месте той
правки (`scope_widget_core.dart:620`) говорит про неё то же самое: «The only
report this failure gets. The boundary above raises it again as an
`ErrorWidget`, but that is what the subtree shows, not what the observer
hears». Сборка — второй и последний случай той же формы.

**Окно закрывается публикацией.** Новое значение в публичном `enum` ломает
исчерпывающий `switch` у потребителя. Пока 0.10.0 не опубликована, оно едет
вместе с шестью уже собранными ломающими правками и не стоит консьюмеру ни
одного лишнего перехода; после публикации — мажорная версия.

## 2. Где

**У пакета уже есть одна точка, через которую проходят все сборки всех
семейств** — `ScopeWidgetElementBase.build()`, последняя строка:

```dart
return _builtChild = buildChild();
```

`lib/src/scope/scope_widget/scope_widget_core.dart:677`. Метод помечен
`@nonVirtual`, а у `buildChild()` во всём пакете **одна** точка вызова —
эта. Ниже неё дерево расходится на четыре реализации:

| `buildChild()` | что зовёт | чей код |
| --- | --- | --- |
| `async_scope_core.dart:1346` | `buildOnState(model.state)` → пять `buildOn*` | пользователя |
| `scope_widget_base.dart:56` | `widget.build(this)` | пользователя |
| `scope_model/base.dart:121` | `widget.build(this)` | пользователя |
| `async_scope_coordinator.dart:118` | `widget.child` | ничей |

`buildOnState` объявлен у четырёх семейств (`async_scope`,
`async_data_scope`, `async_controller_scope`, `lite_scope`), но все четыре
достижимы только через `AsyncScopeElementBase.buildChild()`: `LiteScope` и
`Scope` наследуют асинхронный элемент. Отдельного пути сборки у них нет.

**Значит одна охрана закрывает всё.** Это тот же приём «один хук — одна точка
на все девять семейств», которым закрыт `init()`, и он выбран по той же
причине: точек, которые надо не забыть, не появляется вовсе.

## 3. Правка

```dart
try {
  return _builtChild = buildChild();
} on Object catch (error, stackTrace) {
  notifyObserver(
    (observer) => observer.onError(this, ScopePhase.build, error, stackTrace),
  );
  rethrow;
}
```

**`rethrow` обязателен, и это не осторожность, а правило пакета наоборот.**
Правило волны 17 — «отказ, у которого не осталось адресата, отчитывается и не
бросается» — держится на том, есть ли кому бросать. У `unmount()` элемента
адресата нет (`BuildOwner._inactiveElements._unmountAll()` — цикл без границы),
поэтому там отчёт заменяет бросок. У сборки адресат есть, и он несущий:
граница ошибок Flutter, которая делает `ErrorWidget`. Значит отчёт **добавляется**
к броску, а не заменяет его: видимое поведение не меняется ни на кадр,
наблюдатель начинает слышать.

**Двойного отчёта не будет, и это проверено чтением, а не предположено.** Три
места, где он мог бы взяться:

- **`init()`** отчитывается своим `catch` в том же методе, но **выше** по
  тексту, и оба его выхода — `rethrow` и `Error.throwWithStackTrace` для
  `_initFailure` — уходят из `build()` до `try`, который здесь заводится;
- **`create()`** отчитывается сам, но выполняется не здесь:
  `LiteScopeCoreState.buildOnReady()` отдаёт `_createState` **колбэком** в
  `_LiteScopeCoreWidget(createState: …)`, а зовёт его Flutter при монтировании
  этого виджета — то есть после того, как `buildChild()` вернул;
- **поддерево** внутри `buildChild()` не строится: метод возвращает `Widget`,
  а дети монтируются позже. Отказ, пойманный здесь, — это отказ самого
  билдера, а не чего-то под ним.

## 4. Значение enum

```dart
/// A build of the scope's own subtree.
build,
```

Существительное, как остальные шесть (`initialization`,
`initializationCancellation`, `preparationForDisposal`, `unmount`, `disposal`,
`abandonedWait`). Фраза для `ScopePrintObserver` — `'build failed'`, в общей
форме `'<phrase> failed'`, которой отвечают пять значений из шести.

**Компиляцию уронит сам пакет, и так задумано.** `_failureMessage` —
исчерпывающий `switch` без `default`, и его дартдок объясняет, почему именно:

> This is exhaustive on purpose, with no `default`: [ScopePhase] is defined in
> this same file, so a phase added later fails this switch at compile time
> instead of falling through to a name nobody wrote a phrase for.

То есть механизм под этот момент уже построен, и им надо просто
воспользоваться, а не обходить.

## 5. Ломающесть

Дартдок самого `ScopePhase` предупреждает заранее:

> More values may be added later, so a `switch` over this enum wants a
> `default` branch.

Потребитель, послушавший этот совет, правки не заметит. Потребитель с
исчерпывающим `switch` получит ошибку компиляции — то есть формально это
ломающая правка, и место ей в наборе 0.10.0, рядом с шестью уже собранными.
Строка идёт в раздел текущей версии `CHANGELOG.md`.

## 6. Что остаётся снаружи — граница, а не пробел

Поиск по соседям (`AGENTS.md` §8: «закрыл находку — найди её же в соседней
реализации») даёт три билдера пакета, которые этой правкой **не** закрываются,
и не должны:

- `NavigationNode` — обычный `StatefulWidget`;
- `ListenableSelector` — обычный виджет с `builder`;
- представления `ScopeNotifier` — то же самое.

Причина у всех одна и она структурная: **`onError` требует
`ScopeObservable`**, а `ScopeObservable` — это `debugLabel`, то есть «как эта
вещь называет себя в отчёте». Ни один из трёх скоупом не является, цели для
события нет. Чтобы они попали в наблюдателя, им пришлось бы стать
наблюдаемыми — это другая работа и другое решение, а не хвост этой.

## 7. Проверка

**Тесты** — новая группа в `test/scope_observer_test.dart`:

1. упавший `buildOnReady` даёт `onError(scope, ScopePhase.build, …)`, и
   `ErrorWidget` по-прежнему на месте (`tester.takeException()`);
2. упавший `ScopeWidget.build` даёт ту же фазу — это тест не на второе
   семейство, а **на выбор «одна точка»**: он краснеет ровно у той правки,
   которая ставит охрану в `buildOnState` вместо `buildChild()`.

**Нагруженность** — откатом `catch` по §8.

**Грабли, которые здесь сработают, если о них не помнить** (обе записаны в
`docs/handoff.md`):

- дерево нельзя разворачивать целиком (`pumpWidget(const SizedBox())`), когда
  разбор бросает: отказ вылетает из `Element.unmount()`, обход фреймворка на
  этом кончается, и leak-трекер ловит неутилизированный
  `_UbiquitousInheritedElement`. Забирать только сам скоуп, оставив
  `Directionality`;
- своя подмена `FlutterError.onError` глотает `TestFailure` от упавшего
  `expect`, и прогон **виснет**, а не краснеет. Обработчик возвращать **до**
  проверок, а не только тир-дауном.
