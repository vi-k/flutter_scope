# Волна 6 чистки ревью: `tag` у `ScopeNotifier.value`

> **Состояние на 2026-08-16:** сделано и смержено в `main` одним коммитом.
> **Что это:** отчёт о закрытии P3 №16 — последней мелкой находки полного
> предвыпускного ревью.
> **Связанные записи:** `2026-08-14[10]-project-review.md` (сами находки),
> `2026-08-16[1]`–`[5]` (волны 1–5 чистки).

## Находка

P3 №16: у `ScopeNotifier.value` не было параметра `tag`, хотя он есть у
владеющего конструктора `ScopeNotifier`, у `ScopeNotifierBase.value`, у
`ScopeModel.value` и у `ScopeModelBase.value`. Из четырёх `.value`-конструкторов
пакета без тега оставался ровно один.

Цена — не косметическая. `tag` — единственное, чем в журнале различают два
скоупа одного типа: без него в имени печатается короткий хеш
(`ScopeNotifier<Player>(#4e0b7)`), с ним — имя (`ScopeNotifier<Player>(cart)`),
см. `ScopeWidgetCore.toStringShort`. А `.value` — как раз тот случай, когда два
скоупа одного типа стоят рядом над двумя разными моделями: владеющий
конструктор создаёт модель сам, `.value` берёт чужую.

Заодно правка возвращает правду документации: `doc/a_base.md` утверждает, что
«каждое семейство пробрасывает `tag` в этот конструктор, так что тегировать
можно любой скоуп». До правки это было неверно ровно в одном месте — поэтому
страницы `doc/` не менялись, менять было нечего.

## Правка

`lib/src/scope/d_scope_notifier/scope_notifier.dart`, конструктор
`ScopeNotifier.value`: добавлена строка `super.tag,`. База (`ScopeNotifierBase.value`)
параметр принимала и раньше, так что дальше по цепочке ничего не потребовалось.

Правка аддитивная: `tag` необязателен, существующий вызов `.value` не ломается.

## Тест

`test/scope_notifier_test.dart`, `ScopeNotifier names a .value scope in
diagnostics instead of its hash`. Проверяет три вещи на `toStringShort()`:
тегированный `.value`-скоуп зовётся по тегу, нетегированный — просто типом, и
тег выигрывает у хеша при `showHashCode: true`. Форма взята у теста тега для
`AsyncScope` (`test/async_scope_paths_test.dart`, группа `tag`).

**RED до правки:** компиляция теста падала на
`No named parameter with the name 'tag'` — то есть ровно на отсутствующей
возможности.

**Проверка нагруженности.** Откат правки даёт статическую ошибку, а не
поведенческую, поэтому вместо простого отката прогнали мутацию, которая
компилируется: `super.tag` заменили на обычный игнорируемый параметр
`Object? tag`. Конструктор принимает тег и молча его теряет — тест падает по
существу:

```
Expected: 'ScopeNotifier<ValueNotifier<int>>(auth)'
  Actual: 'ScopeNotifier<ValueNotifier<int>>'
```

Значит тест проверяет проброс тега, а не факт существования параметра. Мутация
после проверки снята.
