## Что сделано

Последний пункт бэклога владельца закрыт, бэклог пуст.

- **`ScopeController`** — базовый класс контроллера: три переопределяемых хука
  (`init`, `onUnmount`, `dispose`), которым не нужен `super`, и три закрытых
  обёртки, которые зовёт скоуп (`performInit`, `performUnmount`,
  `performDispose`). Обёртки держат `mounted`, держат порядок и следят, чтобы
  каждый хук выполнился не больше раза.
- **Три слоя скоупа** поверх машинерии `AsyncDataScope`:
  `AsyncControllerScopeCore` с элементом, `AsyncControllerScopeBase`,
  `AsyncControllerScope<C>` с колбэком `create`.
- **Документация**: `doc/async_controller_scope.md` с зеркалом, раздел в
  `README.md` с зеркалом, категория в `dartdoc_options.yaml` сразу после
  `AsyncDataScope`, строка в `CHANGELOG.md`.
- **Демо**: вкладка `AsyncControllerScope` в `scopo_demo` с тремя примерами —
  обычный путь, упавшая инициализация, скоуп ушёл посреди инициализации.

Буквенные префиксы сняты со всех имён файлов и папок: `lib/src/scope/*`,
`doc/*.md`, `docs/ru/doc/*.md`, папки демо. Единственное не буквальное
переименование — `h_scope` → `full_scope` (везде: код, страница, демо), потому
что папка `scope` встала бы рядом с `scope.dart` и читалась бы как опечатка.

## Три расхождения плана с реальностью

### 1. Пятый путь оказался обычным, а не недостижимым

План отводил отдельный шаг (4.6) на попытку воспроизвести путь «событие
готовности выброшено отменой» и разрешал честно записать, что детерминированного
теста не выходит.

Выяснилось обратное. Мутация «локальный флаг вместо `_initSucceeded`» упала — и
щуп показал почему:

```
PROBE finally: succeeded=false handedOver=true
```

Сценарий «скоуп ушёл, пока шла инициализация» **и есть** этот путь: генератор,
разбуженный после отмены, доходит до `yield`, но подписки уже нет, событие
выбрасывается, и `_initSucceeded` остаётся `false`. Никакого микрозадачного окна
ловить не понадобилось — путь покрыт третьим тестом группы, и критерий защищён
тестом, а не рассуждением.

### 2. Мутация, которую план считал смертельной, не убивала ничего

План обещал, что удаление `_controller?.performUnmount()` из `onUnmount`
элемента уронит все три теста группы. Не уронило ни одного: `performDispose`
сам зовёт `performUnmount`, и порядок в списке вызовов выходит тот же.

Отличить можно только по времени, поэтому добавлен тест, которого в плане не
было: скоуп уходит, пока `init()` припаркован на гейте, и **сразу** после этого
у контроллера уже `['init', 'onUnmount']`, а `dispose` ещё не начинался. Этот
тест мутацию убивает.

### 3. У `scopo_demo` есть тесты

План (и мои слова владельцу до него) утверждали, что тестов у демо-приложения
нет вообще и покрывать демо нечем. Тесты есть — каталог `example/scopo_demo/test`
с одним файлом, который к тому же импортирует папку демо по пути и ломался при
переименовании.

Поэтому третий пример демо получил свой тест: он проверяет, что консоль
показывает `onUnmount` раньше `disposed` и что `initialized` в ней не появляется
вовсе. Пакет доказывает поведение, а этот тест доказывает, что демо его
показывает.

Ещё две мелочи, которых план не предвидел: `test/scope_coordination_test.dart`
импортирует внутренний путь пакета напрямую (переименование его сломало), и
после снятия букв рассыпался алфавитный порядок импортов в `home.dart`
(`directives_ordering`).

## Тесты и мутации

Восемь тестов в `test/async_controller_scope_test.dart` (три на контроллер, пять
на скоуп) плюс один в `example/scopo_demo/test`.

| мутация | что падает |
| --- | --- |
| `performDispose` не зовёт `performUnmount` | порядок вызовов |
| `performDispose` не идемпотентен | второй `dispose` в списке |
| `performUnmount` без проверки `mounted` | лишние `onUnmount` |
| `finally` ничего не разбирает | два теста скоупа |
| локальный флаг вместо `_initSucceeded` | «ушёл во время init» |
| `onUnmount` элемента не трогает контроллер | «отпустил сразу» |
| `disposeAsync` ничего не делает | обычный путь |
| `create` зовётся дважды | конструкторная форма |
| `buildOnReady` строит не ту ветку | она же |
